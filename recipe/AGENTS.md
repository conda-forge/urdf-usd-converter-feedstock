# Recipe maintenance

- For version bumps, check the runtime dependencies in the matching upstream release's `pyproject.toml`. Version 0.4.0 requires `usd-exchange >=3.0.1`. Use the `usd-exchange` Python package as the direct dependency and let it pull in the native libraries. The previous minimum allowed CI to install 2.3.0, which failed `pip check`. [Upstream 0.4.0 metadata](https://github.com/newton-physics/urdf-usd-converter/blob/v0.4.0/pyproject.toml)
- Keep the recipe's Python requirement at `>=${{ python_min }}`. Upstream 0.4.0 declares `>=3.10,<3.14` to match the Python versions supported by its binary dependencies on PyPI. Let conda-forge's compiled dependencies constrain the Python versions available to the solver. Revisit the recipe constraint if the converter itself shows a compatibility issue. [Upstream Python 3.14 tracking issue](https://github.com/newton-physics/newton/issues/4876)
- Keep the lower bound in `python-requires.patch` aligned with the rendered `python_min`. The `tinyobjloader-python` conda package publishes Python distribution metadata under the upstream name `tinyobjloader`, so retain that name in `pyproject.toml`.
- The recipe omits the upstream unit suite because its shared test fixture imports `usd_validation_nvidia`, which is unavailable on conda-forge. The PyPI validator wheel also fails to import with conda-forge's OpenUSD and USD Exchange packages. Revisit the suite when a compatible validator is available on conda-forge.
